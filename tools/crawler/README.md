# allupdsw-crawler — проверка проекта краулером

Краулер обходит все страницы проекта, на десктопе и в мобильной версии, заполняет и отправляет **все формы**
допустимыми, граничными и атакующими значениями и проверяет **безопасность**. Результат: отчёт HTML/JSON
со скриншотами и код выхода для CI.

> ⚠️ **Запускать только на тестовом стенде.** Краулер отправляет формы, создаёт записи и пробует атаки
> (XSS, SQL-инъекции и т.п.). Формы удаления и выхода по умолчанию не трогает.

## Установка

```bash
cd tools/crawler
```

```bash
npm ci
```

```bash
npx playwright install --with-deps chromium
```

Зависимость одна: Playwright 1.63.0 (Apache-2.0), версия закреплена в `package-lock.json`. Нужен Node.js 20 или новее.

## Запуск

```bash
node crawl.mjs --url http://localhost:8080
```

С входом (логин и пароль только через переменные окружения, в файлы их не пишем):

```bash
CRAWL_USER=tester CRAWL_PASS='***' node crawl.mjs --url https://stand.example --login-url /login --bruteforce 10
```

Через файл настроек ([пример](crawl.example.json)):

```bash
node crawl.mjs --config crawl.json
```

Результат лежит в `crawl-report/`: `report.html` (фильтр по уровню, поиск, мобильная вёрстка, светлая и тёмная тема),
`report.json` и `screenshots/`.

Коды выхода: `0` — нет находок уровня `--fail-on` и выше, `1` — есть, `2` — ошибка запуска (стенд недоступен, вход не удался, неверные настройки).

## Что проверяется

| Раздел | Проверки |
|---|---|
| **Функциональность** | все страницы открываются (5xx/4xx), битые ссылки, не загрузившиеся CSS/JS/API, ошибки JavaScript и консоли, номер версии виден на каждой странице (десктоп и мобильный) |
| **Формы** | каждая форма отправляется 11 раз: допустимые значения, пустые (серверная проверка), очень длинные, Unicode/RTL/emoji/кавычки, отрицательные и огромные числа, неверные форматы (email, дата, URL), XSS, SSTI, две SQL-инъекции, обход пути. Сервер не должен отвечать 5xx и показывать трассировку или ошибку SQL. Статические проверки: подписи полей, `autocomplete` у пароля, CSRF-токен в POST |
| **Безопасность** | отражённый и хранимый XSS (формы и параметры URL), SQL-ошибки, SSTI, обход пути, открытый редирект, доступность страниц без входа (повторный запрос без cookie), служебный API без авторизации, служебные файлы (`.git`, `.env`, дампы БД, `phpinfo` и др.), cookie (HttpOnly/Secure/SameSite), заголовки (CSP, защита от фреймов, nosniff, Referrer-Policy, HSTS, раскрытие версии сервера), смешанное содержимое, пароль методом GET, защита от перебора паролей (`--bruteforce N`) |
| **Мобильная версия** | эмуляция Pixel 7 (касания): `meta viewport`, горизонтальная прокрутка, элементы для нажатия меньше 24 px, шрифт полей меньше 16 px, номер версии |

Каждая находка содержит уровень (`critical`, `high`, `medium`, `low`, `info`), название на RU/EN, страницу, подробности,
а для серьёзных проблем ещё и скриншот. Полный каталог проверок: [`checks.mjs`](checks.mjs).

## Настройки

| Ключ CLI | В config | По умолчанию | Описание |
|---|---|---|---|
| `--url` | `url` | — | Адрес стенда (обязательно) |
| `--out` | `out` | `crawl-report` | Папка отчёта |
| `--lang` | `lang` | `ru` | Язык отчёта: `ru` / `en` |
| `--max-pages` | `maxPages` | 300 | Предел страниц |
| `--max-depth` | `maxDepth` | 6 | Глубина обхода |
| `--max-forms` | `maxForms` | 100 | Предел уникальных форм |
| — | `maxVariants` | 3 | Сколько разных query-строк одного пути обходить |
| — | `maxMobilePages` | 60 | Сколько страниц проверять в мобильной версии |
| `--forms` | `forms` | `full` | `none` — не отправлять; `safe` — допустимые и граничные значения; `full` — плюс атаки |
| `--allow-destructive` | `allowDestructive` | false | Отправлять и формы удаления/выхода |
| `--include` / `--exclude` | `include` / `exclude` | — | RegExp для фильтра URL |
| `--public` | `public` | — | RegExp страниц, которые намеренно открыты без входа |
| `--version-regex` | `versionRegex` | `\bv?\d+\.\d+\.\d+\b` | Как выглядит номер версии |
| `--no-mobile` / `--no-security` / `--no-auth-check` | `mobile` / `security` / `authCheck` | true | Отключить раздел |
| `--bruteforce N` | `bruteforce` | 0 | Сделать N неверных входов и ждать 429, капчу или блокировку |
| `--check-external` | `checkExternal` | false | Проверять и внешние ссылки |
| `--insecure` | `insecure` | false | Игнорировать ошибки TLS (самоподписанный сертификат стенда) |
| `--fail-on` | `failOn` | `high` | Порог для кода выхода 1 (`never` — всегда 0) |
| `--delay` | `delay` | 0 | Пауза между запросами, мс |
| `--timeout` | `timeout` | 15000 | Тайм-аут операции, мс |
| `--login-url` | `login.url` | — | Страница входа. В config также `userSelector`, `passSelector`, `submitSelector`, `successSelector` |
| `--storage-state` | `storageState` | — | Готовое состояние входа Playwright (вместо логина и пароля) |
| — | `protectedProbes` | `/api/v1/debug/status`, `/api/v1/access/users`, `/api/v1/access/audit` | Служебный API, который без входа должен отвечать 401/403/404 |
| `--debug` | `debug` | false | Подробный журнал работы |

Противоречивые настройки отклоняются с понятным сообщением:
- `--bruteforce` без входа;
- `login` вместе с `storageState`;
- `--public` при выключенной проверке доступа;
- неверные числа, перечисления и регулярные выражения.

`--no-security` переводит `--forms full` в `safe`.

## Как краулер бережёт стенд и себя

- Обходит только адреса того же сайта. Ссылки и формы выхода, удаления и сброса пропускает (по адресу и по тексту, RU/EN).
- Форму входа не «бомбит»: перебор паролей идёт отдельной проверкой, на выдуманном пользователе и в последнюю очередь, чтобы не заблокировать тестовую учётную запись.
- Ограничивает число вариантов одного адреса (`maxVariants`) и всё обращение к браузеру по времени, поэтому не зависает.
- Пароль не попадает в `report.json`.

## Встраивание в проект

В CI проекта после запуска тестового стенда:

```yaml
- run: git clone --depth 1 https://github.com/lumenods/allupdsw /tmp/allupdsw
- run: cd /tmp/allupdsw/tools/crawler && npm ci && npx playwright install --with-deps chromium
- run: node /tmp/allupdsw/tools/crawler/crawl.mjs --config crawl.json --out crawl-report
  env: { CRAWL_USER: "${{ secrets.CRAWL_USER }}", CRAWL_PASS: "${{ secrets.CRAWL_PASS }}" }
- uses: actions/upload-artifact@v4
  if: always()
  with: { name: crawl-report, path: crawl-report }
```

Краулер дополняет тесты проекта, но не заменяет их. Он проверяет то, что видно снаружи. Права по ролям,
бизнес-логику и сценарии проверяют собственные тесты проекта.

## Тесты самого краулера

```bash
npm test
```

В `test/fixtures/sites.mjs` два учебных сайта:
- **уязвимый**, с заложенными проблемами. Тест требует, чтобы краулер нашёл каждую, не нажал «Выход» и «Удалить всё», экранировал атакующие строки в отчёте и не записал туда пароль;
- **безопасный**, где краулер не должен найти ничего.

Ещё тесты проверяют режимы `none`/`safe`, ограничения обхода, недоступный стенд, ошибки входа,
проверку настроек и их противоречий, коды выхода CLI и экранирование отчёта.
